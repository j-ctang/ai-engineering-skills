**The strongest evidence supports high-volume agent-written PRs, but “hundreds autonomously merged per day by one engineer after 1–2 months” remains unverified.** Stripe reports 1,300+ merged PRs/week with human review; Lauren Tan’s circulated figures are roughly 2,000–2,500/month, self-reported. [Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2), [Tan talk source and transcript analysis](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/)

**1) Lauren Tan — VERIFIED identity and published workflow; UNVERIFIED throughput**

- **Identity/employer:** Lauren Tan is `@poteto`; her own GitHub profile identifies her as a software engineer at **xAI** and React Compiler core-team member. This verifies her public affiliation, not her legal employing entity or a rocket-engineering role at SpaceX. [Her profile](https://github.com/poteto)
- **Videos/posts located:** [Matt Pocock’s YouTube interview](https://www.youtube.com/watch?v=MN9dGgmLyso), titled *LIVE: Poteto … shipping 1,000’s of PR’s a month at SpaceX*; [her original X talk post](https://x.com/poteto/status/2102050467505430555/), originally prepared for Cursor Compile London. [Transcript analysis](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/)
- **VERIFIED public harness:** Her **pstack** plugin runs in Cursor. `/poteto-mode` selects engineering playbooks; overnight work uses isolated worktrees/cloud agents, checkable completion conditions, Cursor `/loop`, and decision logs. [Official guide](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/README.md), [overnight workflow](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/07-overnight.md)
- **VERIFIED review/merge design:** Separate fresh agents verify PRs. Full autopilot assigns one owner per independent PR and repeats independent verification after patch-changing pushes; only a clean verdict on the patch being merged authorizes merging. Coupled changes can remain stacked for human landing. The ordinary “Babysit” workflow stops at merge-ready. [Overnight workflow](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/07-overnight.md), [verification/shipping](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md)
- **VERIFIED task sourcing/guardrails:** The public workflow accepts explicit task queues and includes Slack-report automation for triage, reproduction and draft fixes. Each stage can halt and must pass evidence onward; verification skills use repeatable app-control tooling and receive daily maintenance. [Task automation](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/07-overnight.md), [verification infrastructure](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md)
- **UNVERIFIED internal specifics:** Secondary transcript analysis describes **Control Glass**—a CLI, Chrome DevTools Protocol, traces/heap snapshots and feature map—and **Dune**, architecture/import constraints plus lint/CI. Neither is publicly documented there; no CI vendor or production merge-queue configuration is established. [Qualified account](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/)
- **UNVERIFIED headline:** I found no independent PR audit, evidence of sustained hundreds/day, or confirmation of the **1–2-month** setup timeline. Accounts disagree between 2,000 and 2,500/month and describe substantial maintenance/refactoring; the talk recounts roughly six months of iteration. [Count/timeline analysis](https://redreamality.com/blog/lauren-tan-poteto-trust-before-parallel/), [source comparison](https://carlstack.gravito.dev/blog/agent-work-requires-verifiable-codebase/)

**2) Other credible examples — VERIFIED as first-party reports**

- **Stripe Minions: 1,300+ merged PRs/week, human-reviewed.** Custom Goose-derived harness; prewarmed EC2 devboxes; deterministic “blueprints” interleave implementation with lint/push steps. QA isolation excludes production data/services and arbitrary network egress. CI gets at most two runs before handoff to a human. This is unattended implementation, with human review retained. [Architecture and scale](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2)
- **Ramp Inspect: ~30% of frontend/backend merged PRs** in its January 2026 report. Each session gets a Modal sandbox VM with application dependencies; integrations include Sentry, Datadog, LaunchDarkly, GitHub and Buildkite. Backend tests/telemetry and frontend screenshots/live previews close the verification loop. No daily PR count or fully autonomous merge rate is supplied. [Ramp engineering](https://engineering.ramp.com/post/why-we-built-our-background-agent)
- **OpenAI: ~1,500 opened-and-merged PRs over five months**, initially three engineers; reported average **3.5 PRs/engineer/day**. Practices include repository knowledge, enforceable architecture, agent-accessible runtime/browser observability and agent review. [Engineering report](https://openai.com/index/harness-engineering/)
- **Cursor: hundreds of concurrent agents**, using planners, workers and a judge; later experiments add independent conflict resolution. These demonstrate fleet coordination and large commit volumes, not an audited production PR/day figure. [Initial experiment](https://cursor.com/blog/scaling-agents), [later coordination lessons](https://cursor.com/blog/agent-swarm-model-economics)
- **Anthropic research: 16 agents, nearly 2,000 sessions, ~$20,000 API spend** building a C compiler. Docker isolation, per-agent clones, Git-backed task locks and compiler/test oracles enabled parallel work. It was a research prototype, not a production PR factory. [Experiment](https://www.anthropic.com/engineering/building-c-compiler)

**3) VERIFIED building blocks**

- **Merge queues:** GitHub tests each candidate with latest trunk and preceding queued changes; configure CI for `merge_group`, then require passing checks before merge. [GitHub documentation](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue)
- **Preview environments:** Vercel creates unique branch/PR deployments; Ramp demonstrates fuller sandbox environments with databases and services. [Vercel](https://vercel.com/docs/git), [Ramp](https://engineering.ramp.com/post/why-we-built-our-background-agent)
- **Flaky tests:** Buildkite detects inconsistent results and supports quarantine, recommending **mute over skip** so execution data continues. This is an available industry mechanism; your repo’s prohibition on weakening gates would require a separately authorized policy. [Buildkite](https://buildkite.com/docs/pipelines/configure/tests/test-suites/test-state-and-quarantine)
- **Sandboxes:** Use filesystem **and** network isolation; Anthropic explains why either alone leaves escape/exfiltration paths. Stripe adds disposable QA devboxes with limited privileges and egress. [Anthropic](https://www.anthropic.com/engineering/claude-code-sandboxing), [Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2)
- **PR review bots:** Cursor Bugbot supports repository/nested `.cursor/BUGBOT.md` rules and reports finding acceptance rates; pstack additionally uses independent live verification. [Bugbot](https://cursor.com/docs/bugbot), [pstack](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md)
- **AGENTS.md:** Document setup, build/test commands, conventions and security considerations; nested files scope instructions to packages. It is an instruction convention, with enforcement supplied separately by CI/architecture. [Convention](https://agents.md/), [enforcement discussion](https://openai.com/index/harness-engineering/)
- **Task claiming:** Anthropic’s concrete implementation commits task-lock files; conflicting Git claims force another task choice, and locks are removed on completion. This is one documented pattern, not a universal standard. [Task-lock protocol](https://www.anthropic.com/engineering/building-c-compiler)

**4) VERIFIED failure modes and reported metrics**

- **Coordination failures:** Duplicate work, abandoned hard tasks, lock bottlenecks, drift, conflicting edits and oversized shared files. Cursor moved toward role separation and independent conflict handling; Anthropic used task locks and decomposed test failures. [Cursor initial lessons](https://cursor.com/blog/scaling-agents), [later lessons](https://cursor.com/blog/agent-swarm-model-economics), [Anthropic](https://www.anthropic.com/engineering/building-c-compiler)
- **False confidence:** Stale feature maps and verification tooling can misdescribe behavior; pstack audits these daily and reports product regressions instead of changing documentation to conceal them. [Verification maintenance](https://github.com/cursor/plugins/blob/main/pstack/docs/guide/06-verify-and-ship.md)
- **Runaway iteration/cost:** Stripe caps CI repair attempts; Anthropic reports time blindness and ~$20,000 for its compiler experiment. [Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2), [Anthropic](https://www.anthropic.com/engineering/building-c-compiler)
- **Metrics actually published:** PR totals/share, sessions, token/API spend and review-finding acceptance. These sources do **not establish comparable fleet-wide defect escape, revert or cost-per-accepted-PR rates**. [Stripe](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2), [Ramp](https://engineering.ramp.com/post/why-we-built-our-background-agent), [Anthropic](https://www.anthropic.com/engineering/building-c-compiler), [Bugbot analytics](https://cursor.com/docs/bugbot)
- **Recommended measurement—my synthesis:** Pair agent throughput/cost with change lead time, failure rate, recovery time and rework; add merge/revert rate, escaped bugs, intervention rate and cost per accepted PR. DORA supplies the delivery-quality baseline, while the examples above supply agent-volume/cost measures. [DORA metrics](https://cloud.google.com/blog/topics/financial-services/finra-builds-a-culture-of-improvement-with-dora-and-devops), [agent cost example](https://www.anthropic.com/engineering/building-c-compiler)
